# 同频：黑客松组队空间

## 解决什么问题

黑客松现场有项目想法的人需要找队友，想参与的人又难以判断自己适合哪个项目。「同频」让发起人发布招募需求，让参与者用个人名片介绍自己，并通过可解释的匹配指数辅助选择。

## 运行方式

需要 Python 3.10 或更新版本。在本目录打开 PowerShell，执行：

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python app.py
```

打开 `http://127.0.0.1:5000`。首次启动会自动创建 SQLite 数据库。普通浏览器窗口和无痕窗口可以登录不同账号，演示多人组队流程。

## 演示数据

首次运行后，可在项目目录执行 `python seed_demo.py` 加入演示数据。脚本只新增演示数据，不清除已有资料；同一数据库再次运行不会重复写入。

四个演示昵称为「演示·许一诺」「演示·阿澈」「演示·小羽」「演示·苏禾」，共同密码是 `Demo12345!`。这组密码只用于本地演示，正式开放服务前应删除演示账号或换成安全的私有账号。

建议用普通窗口登录「演示·许一诺」，在申请箱看到阿澈的待处理申请；用无痕窗口登录「演示·阿澈」，查看「演示·课间灵感站」的 70 分匹配指数。许一诺接受申请后，两边的成员人数会自动更新。小羽的申请已接受，可用来查看已有成员状态。

如果要让同一局域网中的其他设备访问，可在启动前设置 `APP_HOST=0.0.0.0`，再使用这台电脑的局域网 IP 和端口 5000 打开。使用时还需允许系统防火墙放行该端口。此运行方式适合受信任的现场演示；公网部署需要另配正式服务器和 HTTPS。

```powershell
$env:APP_HOST = "0.0.0.0"
python app.py
```

`APP_SECRET_KEY` 可设置为固定随机字符串，使服务重启后登录会话仍有效。数据库默认位于 `instance/team_matcher.sqlite3`；`instance/` 已列入 `.gitignore`，不应提交含用户资料的数据库。

## 核心流程

1. 两个人分别注册并填写个人名片：昵称、技能、兴趣、简介和可投入时间。联系方式默认隐藏。
2. 一人发起项目，填写所需技能、方向、时间要求和人数上限。
3. 另一人在项目页查看匹配指数和技能、方向、时间三个分项，然后申请加入。
4. 发起人在申请箱查看申请者名片，接受或拒绝申请。
5. 接受后队伍成员和名额更新。其他已打开页面每 2.5 秒读取服务器最新数据；回到隐藏的标签页时也会立即同步。
6. 正式成员从顶部「项目讨论区」选择项目，发送文字消息；队长和已加入的成员可以看到新消息。未加入的人不能查看或发言。
7. 普通成员退出时填写理由，提交后立即退出并空出名额。理由会作为一条记录留在小组讨论中；退出后本人不能继续查看讨论区。如需回来，可再次申请，仍须队长审核。

登录后的「推荐给你」只列出仍可申请的项目，并按匹配指数排序。已发起、已加入、已申请或已满员的项目放在「其他项目」，标明状态，仍可打开查看。未登录时显示全部项目。

名片支持按昵称、技能、兴趣检索，名片链接可以分享给访问同一服务的人。「我的名片」默认只显示已保存的资料和已参与项目；项目会标明「发起人」或「成员」，点击可打开项目。申请被接受后，名片上的项目列表会随页面同步更新。点击「编辑名片」才会出现表单；取消编辑不会保存，保存后返回名片展示页。待处理或已拒绝的申请不会列为已参与项目。

## 技术实现

- 前端：原生 HTML、CSS、JavaScript，无前端构建工具。
- 后端：Python、Flask，提供登录、名片、项目、申请、讨论和退出等 JSON 接口。
- 数据：SQLite，保存用户、项目、申请、成员关系和文字消息。已有数据库启动时会自动建好新增的消息表。
- 密码：Werkzeug 哈希，不保存明文密码。

匹配指数由 Python 在服务器计算：所需技能命中率最多 60 分，项目方向命中率最多 25 分，投入时间最多 15 分。页面同时展示三个分项和命中的标签。资料不完整时不显示分数。这个指数帮助发现共同点，不能代替面对面的交流。

浏览器每 2.5 秒请求一次 `/api/state`。正在输入名片、项目或登录表单时，页面不会因为自动同步而重画表单；提交后立即读取最新数据。申请与接受操作在 SQLite 写事务中再次检查状态和队伍人数，避免重复申请或超员。

讨论消息通过单独接口读取和发送，每条限 1–500 字。服务端在每次读取、发送时核对成员身份。退出操作在同一数据库事务中写入退出理由、移除成员并将原申请标记为已退出；重新申请会重新进入待队长审核状态。讨论页定时更新消息列表，保留输入框里尚未发送的文字。

## 边界与处理方式

1. **多人同时接受申请**：接受时开启 `BEGIN IMMEDIATE` 写事务，在同一事务内检查人数并加入成员；满员则返回明确错误。
2. **个人信息**：公开名片只展示用户主动填写的信息；联系方式默认隐藏，只有本人勾选才公开。用户仍需谨慎填写简介等公开字段。
3. **网络中断**：自动同步会提示失败；恢复连接后重新读取数据。提交操作由服务器确认，失败时不会在页面上假装成功。
4. **匹配偏差**：技能和方向采用标签精确匹配，相近词可能未被识别。页面展示命中依据，让用户自行判断。
5. **服务规模**：2.5 秒轮询适合小型活动演示。人数明显增多时，应改用更高效的更新机制并评估数据库容量。
6. **讨论区访问**：只靠页面隐藏不够，因此读取和发送消息的接口都在服务器检查正式成员关系。成员退出后立即失去访问权限，历史消息留给仍在组内的人。

## 遇到的问题与解决方式

前端原型最初把数据保存在浏览器，两个账号无法共享状态。现在所有操作都写入服务器的 SQLite 数据库，页面定期读取最新状态。另一个问题是自动刷新可能清空正在输入的内容，因此编辑表单期间只更新内存数据，保留表单；提交后再刷新页面内容。
